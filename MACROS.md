# Macro index and reuse rules

Read this before writing a new macro. Most measurements here (a spectrum, a
ratio, a purity, a dR or ptRel shape) already have a macro that does it. A
fresh rewrite usually loses the fixes already in the old one: the
`FindBin(hi - 1e-6)` upper edge, `Scale(1,"width")` after integrals, the
`h_vz_triggerOn` denominator, projecting each file's own jet-pT axis. Several of
those bugs have been reintroduced by exactly this kind of rewrite.

## Rules for a measurement task

1. **Look first.** Check the index below, then search by histogram name:
   `grep -rl h_<name> src/plots src/newFractionCalculation src/calculate*`.
   Most macros open with a header comment saying what they plot and how they
   normalize. Read it.
2. **Change inputs freely.** Most macros keep their input paths, pT windows,
   centrality class and output dir as `const` values at the top of the file.
   Pointing these at the file you need is expected, not a rewrite. The b-jet
   chain macros take the jet collection as an argument instead
   (`headers/functions/jetCollectionInputs.h`).
3. **Copy before changing logic.** If the measurement needs different logic
   (a new projection, normalization or overlay), copy the macro to a new name
   beside it and edit the copy. Don't change the behavior of a macro other
   work depends on unless the user asks.
4. **Be up front.** In the reply, say which macro you used, which inputs you
   changed, and whether you copied or edited it. If you wrote something new,
   say why no existing macro fit.
5. **Write new only when nothing fits.** Build it from `headers/plotting/`
   (`coarseCent.h`, `plotStyle.h`, `ratioPanel.h`) and the newest macro of the
   same kind, not from scratch. Add it to the index below.
6. **Don't revive dead macros.** Undated or 2025-era macros with no header
   comment often include `goldenFileNames.h` from the sibling repo, take
   pre-2026 file names, or no longer compile. The plain
   `plotJetPt.C` / `plotMuonPt.C` / `plotMuonPtRel.C` / `plotJetEta.C` are like
   this. Use a newer macro instead, and tell the user if one turns out stale.
7. **Check the input generation.** Before comparing two files, see the
   *Scan generation* section of CLAUDE.md (`provenance` TNamed, the
   `h_mixedMuonPtRel_recoJetPt` marker).

## Directory map

| path | contents |
|---|---|
| `src/scanning/{PbPb,pp,PYTHIA,PYTHIAHYDJET,HYDJET}/` | scans (forest → histogram files), condor drivers, per-sample scripts |
| `src/skimming/` | skims ahead of scanning |
| `src/plots/<observable>/` | plotting macros, one folder per observable (`jetPt`, `muonPtRel`, `muJetDr`, `bPurity`, `dimuonMass`, `triggerEfficiency`, `hiBin`, `vz`, …) |
| `src/plots/quick/` | old one-off checks. Not maintained, don't treat as a reference |
| `src/newFractionCalculation/` | inclusive jets-per-Z, RAA, RCP, calo vs PF, fake-jet subtraction |
| `src/calculateJetsPerZ/` | inclusive jets-per-Z (current driver) and its systematics |
| `src/calculateBJetsPerZ/` | b-jet chain: pp spectrum → unfold → muon reco eff → tag freq; PbPb `bJetChain_caloJets_PbPb.C` |
| `src/bPurityCalculator/`, `src/templateFitter/` | older b-purity fitting (current fits: `headers/functions/caloJetBPurityFit_*.h`) |
| `src/systematics/` | per-source and total systematics (`*_caloJets_pp.C`) |
| `src/unfoldTest/` | unfolding closure tests and JEU shifts |
| `src/muonReconstructionEfficiencyCalculator/` | tag-and-probe muon reco efficiency |
| `src/jetEnergyResolution*/` | JER measurement and smearing |
| `src/randomCone/` | random-cone hiBin-shift study |
| `headers/plotting/` | shared plot helpers. Use them |
| `headers/functions/` | physics helpers (`getPtRel.h`, `getDr.h`, `getCentBin*.h`, fit cores, `jetCollectionInputs.h`) |
| `headers/fitParameters/` | stored fit outputs (reweights, efficiencies, ptRel fit params) |
| `headers/config/` | scan run-time flags |
| `tools/` | `syntaxCheck.sh`, ultraFine → nominal centrality merging |
| `catalog/` | SQLite catalog of scan files (`build_catalog.py`, `queries.sql`) |
| `fileNames/` | forest file lists that scans read |
| `rootFiles/scanningOuput/<system>/` | scan outputs (**"Ouput" is the real spelling**) |
| `workflow/workflow.org` | step order for reweights and derived inputs |
